# RITUAL BLOCKCHAIN - KNOWLEDGE BASE

## OVERVIEW

Ritual is the most expressive blockchain in existence — a sovereign EVM-compatible L1 purpose-built for heterogeneous compute, with a focus on Crypto × AI. It makes smart contracts actually smart by enabling native on-chain AI, scheduled transactions, and expressive computation.

Key innovations include:
- EVM++ – extended EVM with compute precompiles, account abstraction, and EIP extensions
- Enshrined AI Models – first-class on-chain AI with verifiable provenance
- Scheduled Transactions – recurring execution without external keepers
- Resonance – efficient fee mechanism for heterogeneous workloads
- Symphony – novel consensus protocol
- Infernet – decentralized oracle network for AI compute
- Smart Agents – verifiable, autonomous on-chain agents

## EVM++

EVM++ is Ritual's backwards-compatible extension of the Ethereum Virtual Machine (EVM). It adds expressive compute precompiles to build "actually smart" contracts, along with native scheduling, built-in account abstraction (via EIP-7702), and support for the most wanted EIP extensions. Its core components include:

## EVM++ Components

- Scheduled Transactions – recurring, conditional execution without external keepers
- Account Abstraction – native smart contract accounts
- EIP Extensions – early support for EIPs like Ed25519, secp256r1, unlimited contract size, and the PAY opcode
- Expressive Compute – heterogeneous compute precompiles (AI inference, ZK proving, TEE execution, etc.) powered by modular execution sidecars

## EVM++ SIDECARS

EVM++ Sidecars are modular, containerized components that run parallel to Ritual's execution client, implementing heterogeneous compute precompiles via the standard EVM precompile interface. Unlike traditional EVM precompiles (implemented directly in the execution client), Ritual's compute precompiles are disjoint sidecars — meaning anyone who can architect a containerized sidecar can have their computation enshrined on-chain.

Currently supported sidecars include:

- Classical ML Inference – tree-based and regression-based models
- LLM Inference – state-of-the-art language models
- ZK Proving & Verification – verifiable, tamper-proof computation
- TEE Execution – privacy-preserving computation in secure enclaves
- Chain Abstraction – read/write state to other blockchains from Ritual
- Network Calls – arbitrary HTTP requests from smart contracts

## Smart Agents

Smart Agents on Ritual are verifiable, autonomous on-chain agents with provable execution and cross-chain capabilities.

Key capabilities include:
- Verifiable Execution – TEE-based guaranteed autonomous operation with blockchain provenance
- Enshrined AI Inference – native on-chain AI powering agent decision-making

Ritual agents also support autonomous evolution — self-improving with verifiable performance gains, adaptive strategy evolution via DAOs, and automated failure detection/recovery.

## Infernet

Infernet is Ritual's decentralized oracle network (DON) purpose-built for AI workloads, launched in November 2023. It's powered by 8,000+ independent nodes executing arbitrary workload containers.

Key features (v1.0.0+):
- On-chain payments (audited by Trail of Bits & Zellic)
- Verification of compute via modular proofs
- Streaming responses for real-time workloads

Bridging Infernet ↔ Chain, Ritual extends Infernet's capabilities by:
1. Using Resonance to route and price compute requests to Infernet nodes
2. Extending execution sidecars to tap into the Infernet mesh
3. Offering Web2 adapters as drop-in API replacements with privacy and verifiability
4. Enabling verifiable, reproducible Web2 requests via modular computational integrity

For node operators, this hyperscales workload demand and earnings. For developers, it's a drop-in replacement offering competitively priced, verifiable compute.

## Resonance

Resonance is Ritual's state-of-the-art transaction fee mechanism designed for heterogeneous compute, efficiently matching supply and demand to offer optimally priced execution.

The problem: Existing fee mechanisms (like multi-dimensional EIP-1559) fail as transaction heterogeneity grows — leading to poor pricing, limited support for new transaction types, and failed executions.

How it works:
- Users specify a `valuation` and can prioritize speed or cost
- Nodes specify private `cost functions` per transaction and can specialize in specific compute types
- Brokers — sophisticated, profit-seeking agents — compute optimal matchings between transactions and nodes, pocketing the spread

Key benefits:
- Efficiently prices any type of compute without protocol-level constraints
- Enables node specialization and parallel execution
- Supports private execution via multi-party assignment
- Works alongside Symphony for network-level specialization

Future work includes scheduled transaction pricing, decentralizing the auctioneer, streaming transaction support, and posted price mechanisms (Uber-like UX).

More details on the [Resonance](/whats-new/resonance) and [Resonance Architecture](/architecture/resonance) pages.

## Scheduled Transactions

Scheduled Transactions enable recurring, conditional invocation of smart contract functions at the top of a block, without external keepers. Ritual is one of the first EVM blockchains to enshrine native scheduling.

How it works:
- A predeploy `Scheduler` contract lets developers register callback frequencies, conditional execution functions, and fee preferences via `Scheduler.schedule()`
- Block producers include these as `SystemTx` transactions at the top of each block, ensuring priority execution
- Developers can cancel future invocations and receive refunds via `Scheduler.cancel()`

Two execution modes:
1. Homogeneous compute — standard EVM execution included by block producers
2. Heterogeneous compute — routed through [Resonance](/whats-new/resonance) for optimal pricing and node assignment

Key benefits:
- Top-of-block priority for critical operations like oracle updates
- Keeper-free automation — no reliance on external services
- Conditional logic — optional view functions dictate real-time execution
- Dedicated fee markets — separately priced from standard transactions
- Enables autonomous apps like smart agents

## Symphony

Symphony is Ritual's novel consensus protocol that replaces traditional replicated execution with an Execute-Once-Verify-Many-Times (EOVMT) model, purpose-built for heterogeneous, resource-intensive workloads.

The problem: Traditional blockchains require all nodes to re-execute every transaction — unscalable for heavy compute like AI inference or ZK proving.

Three key innovations:

1. Execute-Once Semantics — A single node executes heterogeneous operations and generates succinct sub-proofs; validators slot in gossiped outputs instead of re-executing
2. Distributed Verification via Partitioned Proofs — Large models are split into sub-models with sub-proofs, stored off-chain, and verified by assigned validator subsets reaching quorum
3. Optimized Committee Election — Smaller validator groups form quorums for cases where no succinct proof system exists

Flexible proof systems include TEE attestations (initial), ZK proofs (in development), and hybrid approaches.

Safety is maintained with ≥⅔ honest stake, and liveness through economic incentives. Symphony is consensus-gadget agnostic, initially targeting aBFT protocols. More details on the [Symphony overview](/whats-new/symphony) and [Symphony architecture](/architecture/symphony) pages.
